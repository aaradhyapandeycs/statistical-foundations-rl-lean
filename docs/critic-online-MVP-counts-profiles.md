## Lemma 5.11: final profile-cardinality bound

The indexed statement is `StatisticalRL.Statements.Lemma5_11`; its application is `Lemma5_11_holds`. The source threshold and final expression are retained. The proof counts profiles generated by every finite episode-by-stage state-action row table, which includes the algorithm’s possible cumulative-count profiles. It derives the actual pre-episode profile-index bound, includes K=1, and uses a ceiling comparison family so that every attainable profile is counted. The stronger row-table result does not depend on how empirical models are triggered.

C15 is an intermediate proof issue, not a false final bound: for K=3 and cumulative count 2, the source profile index is 2, but the displayed comparison family `{0,…,log₂K}` omits that index if its integer endpoint is floored. The ceiling family fixes the inclusion and yields the same printed cardinality bound.

## Lemma 5.12: corrected trigger scope and final sum

The indexed result is deliberately named `StatisticalRL.Statements.Lemma5_12_powerOfTwo_corrected`, with application `Lemma5_12_powerOfTwo_corrected_holds`. It retains K≥2, the k-outer/h-inner episode-stage sum, the max-one denominator, pre-episode table timing, and the factor `4SAH log₂K`. The operational fold tracks per-successor pending counts, row-local resets, stored completed-batch size, and the source stage clock; the proof handles arbitrary realized row/successor traces. A dyadic-block argument proves the final sum without the manuscript’s separate pointwise factor-two claim.

There is a source inconsistency that requires this corrected label. The prose at lines 1213–1217 specifies a trigger when a count reaches a power of two and says empirical kernels update only at powers of two. Algorithm line 1280 instead literally gives the trigger set `{1,2,…,2^(log₂K)}`, which contains every positive integer through K. Under that literal reading, with S=A=H=1 and K=32, the only row triggers on every visit and stores a batch size of 1. The inverse-count sum is 32, exceeding `4 log₂32 = 20`. This is a source-level calculation, not a Lean formalization of the literal trigger. The proved variant follows the doubling prose and explicitly does not claim that the displayed literal set satisfies Lemma 5.12. The profile-to-empirical-kernel assertion at lines 1531–1533 also relies on power-of-two updates; it is not certified for the literal line-1280 reading. C13 records both the trigger conflict and the distinct invalid factor-two step.
