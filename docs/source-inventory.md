## What the scanner does

- Follows braced `input`/`include` commands in execution order from the main source. Hashes included files and the local class. Reads the local class for theorem counter declarations; class/package rendering macros are not included as mathematical content.
- Masks percent comments, comment environments and macro definitions without losing source line positions. Recognizes one-argument empty/identity wrappers (including this source's `arxiv`/`book` choices). The wrapper semantics follow the active source definitions, regardless of the macro names.
- Reads theorem environment definitions and shared counters; resets chapter counters; distinguishes equation rows, suppression (`notag`/`nonumber`), subequation letters and explicit tags. Numbering is a simulation, not a compiled `.aux` certificate.
- Records all supported displays, including unlabeled and unnumbered ones. Records labels and cross-reference/citation sites, explicit proof environments and headings matching proof/analysis/step cues.
- Adds notation/prose definition candidates. These may duplicate surrounding work items and require semantic classification. Labels are preferred IDs; unlabeled IDs use chapter/kind/number or a content hash rather than line numbers.

## Limits and remaining coverage work

- This is a lexical scanner, not a general TeX interpreter. Arbitrary macro expansion, package-specific counters, conditionals, catcode changes, dynamically generated input paths, and all possible custom environments are unsupported. Unsupported control commands are reported when detected. Only simple wrapper macros are expanded.
- Counter predictions must be checked against the authoritative rendered PDF. An align environment can contain several numbered rows; row count differs from display-environment count. Figures/tables are context entries and their printed numbering is not predicted.
- Keywords cannot decide mathematical importance or identify every inline definition, unnamed lemma, standing assumption, proof gap, cited external premise or substantive proof step. Every source paragraph, including exposition, must still receive independent semantic review. No count here certifies exhaustive mathematics coverage.
- Proof-heading regions end at the next heading of equal/higher level. Adjacent-result links are search hints only; no statement-to-proof pairing or dependency edge is certified.
- The inventory initializes every item as unformalized; it does not inspect Lean implementations, create frozen anchors, or satisfy the source dependency graph's approval/audit gates.
- Rerunning regenerates the source checklist and resets statuses. Keep formalization evidence in a separate reviewed ledger keyed to source IDs. IDs without labels can change when the source changes.
